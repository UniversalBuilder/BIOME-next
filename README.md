# BIOME-next 3.0.0-alpha.2

BIOME-next is the actively developed successor to [legacy BIOME 2.x](https://github.com/UniversalBuilder/BIOME). It redesigns project management around readable documentary catalogues and separate original-image storage. The legacy repository preserves the old application and its history. This is a development preview, with a different data format; it is not an automatic upgrade or database migration.

## Typical workflow

Request → project → retained originals → agreed scope → notebook and experiments
→ frozen delivery → activity report. A short consultation can use a minimal
record; script development can retain versioned files and multiple deliveries.

## Current scope

Windows local application, project notebook, linked files, verified data receipt,
delivery snapshots, activity reports, recoverable project removal, backups and
explicit catalogues. Three fictional demo projects can be installed from the
Catalogue screen. Example images are generated by the application; no research
or personal data are included.

A catalogue contains project records, notebook text, scripts, small attachments,
delivery snapshots and common lists. Original images remain in separate data
folders, on the same computer or a network storage. Select that folder when
creating a project, or link it later. Back up the catalogue and original data
separately.

The current UI is French. Full internationalisation, English by default and
optional JSON language packs remain planned for a future milestone.
This preview is not presented as a finished English-language release.

## Build on Windows

Install Python 3.12 or a compatible version. From the source root:

```powershell
.\src\biome\Build-Windows.ps1 -Python python
```

The portable application is produced in `src/biome/dist/BIOME`. Keep the entire
folder together. Chrome or Edge is required for its dedicated app window. No
administrator rights are needed to run it from a writable user folder.

On first launch, create or open a catalogue, or install the fictional demo in a
separate folder. The last chosen catalogue is remembered. Settings and logs live
in `%LOCALAPPDATA%/BIOME`, outside the program folder.

## Tests

```powershell
.\src\biome\build-env\Scripts\python.exe -m unittest discover -s src/biome -p 'test_*.py'
node src/biome/test_project_sort.js
.\src\biome\build-env\Scripts\python.exe src/biome/check_standalone.py src/biome/dist/BIOME/BIOME.exe
```

The tests use generated fixtures. They do not require a research catalogue,
developer credentials or a personal home directory.

## Version and data formats

Application version: 3.0.0-alpha.2. Project format: 1.1 (reads 1.0 and 0.1-draft).
Catalogue identity format: 1. Application release versions are independent of
project format versions. No implicit rewrite of existing project data is needed
to read an older supported format.

## Publication status and licence

The published source tree excludes legacy Git history, real project catalogues,
personal exports, private screenshots, credentials, generated builds and dependency environments.
Documentation screenshots use only the fictional demo.
`source-manifest.json` records the included files and their SHA-256 hashes. This
does not audit the history of any pre-existing repository.
